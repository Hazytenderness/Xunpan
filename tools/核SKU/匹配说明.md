# 1688 核 SKU：判同款、选规格、取价格和包装

你拿到一块 ataous 日本站（亚马逊日本）的款，每款带 1–3 家 1688 货源候选的核页数据。任务是逐款逐家判断：1688 页面卖的是不是这个亚马逊款，是的话选出对应的 SKU，取页面价格和包装。结果会同步到运营网站当采购成本，所以宁可标低置信，也不要猜。

## 输入

`<块目录>/input.json`：一个数组，每款有：
- `亚马逊标题`（日文）、`类目`、`日元价`、`FBA日元`（FBA 配送费，越高越大件）、`亚马逊图`（相对块目录的本地图片路径）
- `候选`：每家有 `标题`、`1688类目`、`规格属性`、`规格价格`（带下标 `i`）、`阶梯价`、`起订量`、`单位`、`商品属性`、`包装信息`（按 SKU 的长宽高 cm、重量 g）、`主图`（本地图片路径）、`规格图网址`（[规格名, 网址] 列表）。核页失败的只有 `核页` 一栏说明原因。

## 每款每家都要做

1. **看图**：每款只 Read 一张 `对照图`（拼好的一张：最左是 AMAZON，后面按条目号排各家 1688 主图），对比外形、结构、材质。为了省 token：一次回合里并行 Read 几款的对照图；不要单独打开 `亚马逊图`、`主图`；规格图只在 SKU 要靠图分辨、文字又看不出时才下载（`curl -s -A Mozilla/5.0 -o <块目录>/img/文件 网址`），每款最多 2 张。文字信息足够判断时直接判断。
2. **定亚马逊款规格**（每款一次）：读日文标题，用中文写一句采购规格，写清品类、关键尺寸/容量/档位/材质/功能。对标是多件装（标题里有「N枚セット」「N個入り」「N本組」「Nパック」之类，N>1）时，规格末尾写「N个装」，`装数` 填 N，否则 `装数` 填 1。
3. **判结论**：
   - `同款`：同一种货，关键规格对得上（颜色不同不算问题）。
   - `近似`：同品类，但有可见差异，比如档位、尺寸、功能少一项。也要选最接近的 SKU，在 note 里写清差在哪。
   - `款不对`：明显不是一种货，或者结构、用途不一样；材质不同导致功能或外观明显不同的（如密胺不能微波、法兰绒保暖对网布凉感、一次性铝箔对硬质板）也算。
   - 材质替代【用户定·2026-10-08】：外观、结构、用途和尺寸都对得上，只是面料换成常见的便宜替代（仿真丝替桑蚕丝、涤纶珊瑚绒/超细纤维替纯棉），判 `近似`，note 开头写「材质替代：」并写清两边材质。`sku_index`、`sku`、`price`、`pack` 都填 null。
   - `下架`：页面无商品数据，或者 `状态` 不是 `PUBLISHED`。`未抓到`：没有核页数据。这两种只填结论和 note。
4. **选 SKU**：从 `规格价格` 里选和亚马逊款最对应的一个。尺寸、容量、件数、档位优先对上，颜色次之；同价的多个颜色选第一个就行。记下 `sku_index`（就是 `i`）、`sku`（规格名原文）、`price`（该 SKU 的价格，数字）。页面没有 SKU 列表时，`sku_index` 填 -1，`sku` 填「无规格」，`price` 取 `阶梯价` 第一档。
5. **unit_count**：所选 SKU 一份里含几个亚马逊单件。SKU 名或标题写了「10只装」「5个/包」「一套3件」就填对应数字，否则填 1。拿不准就填 1，在 note 里写「装数待确认」，confidence 不高于 中。
6. **pack**：只从 `包装信息` 里取所选 SKU 那一条（对 `sku1`/`sku2` 名字），写 `{"长":…,"宽":…,"高":…,"重量克":…}`。没有对应条目、任何一项是 0 或空，或者数值明显离谱（比如水杯 0.5 cm 高、毛巾 20 kg），就填 null。不估算，不从商品属性里拼。页面不分 SKU、只有一条包装数据，而且所选 SKU 是页面唯一规格时，可以取这条。
7. **confidence**：
   - `高`：图和规格都清楚对得上，SKU 唯一明确。
   - `中`：同款可能性大，但有细节看不出（材质、档位、尺寸没写全），或 SKU 要在几个里挑。
   - `低`：图看不清、规格对不上号，或者只是同品类。
8. **note**：一句中文，平铺直叙，写判断依据和要确认的点，比如「同款，SKU 选 40×80cm 单条装；页面未写克重」。不写客套话，不用 emoji。

## 输出

按款顺序做完后一次写到 `<块目录>/match.json`（款多时可以每 10 款追加写一次，不要每款写一次）。对标品要另配件的（比如套装带布套、粘贴件，页面要单买），在 note 里写明配件和页面价。回报只写统计和拿不准的款，不要逐款复述。格式：

```json
{"款": [
  {"序": 92, "规格": "增压微气泡固定花洒头（5档出水，带止水键）", "装数": 1,
   "候选": [
     {"条目": "H0123", "offerId": "…", "结论": "同款", "sku_index": 3, "sku": "…原文…", "price": 8.3,
      "unit_count": 1, "pack": {"长": 20, "宽": 5, "高": 3, "重量克": 150}, "confidence": "中", "note": "…"}
   ]}
]}
```

input 里每款、每家都要出现在输出里，一家不漏。写完用 `python3 -c` 读一遍 match.json，核对款数、候选数和 input 一致，再回报：款数、各结论的家数、你拿不准的款。

## 硬规则

- 只读本地文件、下载图片，不打开 1688 网页，不调用任何付费接口。
- 价格和包装只取页面数据，不编不估。
- 不要修改 input.json 和块目录以外的任何文件。

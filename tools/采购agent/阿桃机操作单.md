# 阿桃机操作单（2026-10-30）

> 用途：去阿桃机（Windows）上一次做完的事，照顺序做。三种做法都能用这张单：人坐过去、远程桌面连过去、或把「给 Codex 的指令」那段发给阿桃机上的 Codex。
> 每一步都写了「看到什么算成功」和「看到什么就停」。停了就截图发给 c总，⛔别自己往下猜着做。
> 规则依据：AGENT.md；接入总方案见 [接入方案.md](接入方案.md)。

## 第 1 步 · Xunpan 补推（最急）

**为什么**：阿桃机从 10-27 12:26 起推不上 GitHub。它推送时同时推 main 和 windows-port（`tools/lib/port.py`），main 上有它本地没有的提交，所以整次被拒，台账都积在本机。

**什么时候做**：整 10 分钟刚过（定时任务刚跑完），免得它正好也在推。

打开 PowerShell，先找到 Xunpan 文件夹（不知道在哪就跑这条，会列出路径）：

```powershell
Get-ChildItem E:\ -Directory -Recurse -Depth 3 -Filter Xunpan -ErrorAction SilentlyContinue | Select-Object FullName
```

进到那个文件夹（把路径换成上面列出来的）：

```powershell
cd E:\CodexP\Xunpan
```

逐条跑：

```powershell
git status
```
- 成功：显示 `On branch windows-port`，下面没有红色的 `modified`。
- **停**：有 `modified`、`Untracked` 一大片，或者不在 windows-port 分支 → 截图。

```powershell
git fetch origin
git merge origin/main
```
- 成功：显示 `Merge made by` 或 `Already up to date`。
- **停**：出现 `CONFLICT` → 截图，别动文件。要撤回就跑 `git merge --abort`。

```powershell
git push --atomic origin HEAD:main HEAD:windows-port
```
- 成功：最后两行带 `main -> main` 和 `windows-port -> windows-port`。
- **停**：`rejected` → 截图（多半是这期间又有人推了 main，重跑 fetch、merge、push 一次；再失败就停）。

做完告诉 c总，c总在这边核对 GitHub 上有没有 10-28 以后的记录。

## 第 1.5 步 · 拿采购agent 的代码（另开文件夹，⛔别切旧系统的分支）

代码在 GitHub `Hazytenderness/Xunpan` 的 `agent/接入` 分支 `tools/采购agent/`。旧系统的定时任务就在 Xunpan 文件夹里跑，**⛔不要在那个文件夹里 `git checkout agent/接入`**，那等于把旧系统的代码换掉。另开一个文件夹：

```powershell
git fetch origin
git worktree add ..\Xunpan-采购agent agent/接入
```

- 成功：Xunpan 旁边多一个 `Xunpan-采购agent` 文件夹，新代码在 `tools\采购agent\`。
- 验一下（要装了 Python）：进到 `..\Xunpan-采购agent\tools\采购agent`，跑 `python inquiry.py --selftest`，最后一行应是「不过 0」。
- **停**：`already exists` 或报错 → 截图。

## 第 2 步 · 停掉「程序自动写不做」

**为什么**：用户 10-30 定「不做只能人在货源核实里点」。现在阿桃机旧系统 `tools/lib/operating-policy.mjs` 第 37–55 行会自动写不做：食品接触、或「最新倍数小于 2」的款，直接把 `选品.阶段` 写成「不做」（`排除处理人` 是 AI）。不先停掉，清回去的款还会被写回来。

**改法（c总 在这边准备，⛔不在阿桃机上手改）**：
- 食品接触、倍数不够的款：只是不进询盘，⛔不写「不做」；
- 倍数门槛从「>2」改成「≥3」（AGENT.md 9.4）。
- c总 会先在 GitHub 的 Xunpan 仓库开一个分支放这处改动，**要你点头才推**；推好后你在阿桃机上跑：

```powershell
git fetch origin
git merge origin/<c总给的分支名>
git push --atomic origin HEAD:main HEAD:windows-port
```

**之后清已经写错的不做**：c总 先只读拉一份清单，分清哪些是人点的、哪些是程序写的（看 `排除处理人`），给你看完再撤回程序写的那部分。

## 可选 · 配远程连接，以后不用跑过去

在阿桃机上开 Windows 自带的 SSH 服务，再把它加进 Claude 应用的 SSH 连接里，c总 就能直接在阿桃机上开会话。这是改那台电脑的系统设置，要你本人做（用管理员身份打开 PowerShell）：

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
```

然后在 Mac 的 Claude 应用里添加 SSH 连接（地址、用户名由你填，c总 不碰密码）。阿桃机和 Mac 不在同一个网络的话，还要能从外面连进去（比如 Tailscale），这个到时候再说。

## 给 Codex 的指令（远程让阿桃机上的 Codex 做第 1 步时，原样发给它）

```
只做 Xunpan 仓库的同步补推，不做别的，不发任何 1688 消息，不改任何文件内容。
1. 在 Xunpan 仓库跑 git status：不在 windows-port 分支、或有未提交改动，就停下来报告原样输出。
2. git fetch origin，然后 git merge origin/main：出现 CONFLICT 就 git merge --abort 并报告冲突文件名，停。
3. git push --atomic origin HEAD:main HEAD:windows-port：被拒就重新 fetch、merge、push 一次；再被拒就停，报告原样输出。
4. 成功后报告：git log -3 --format="%h %ci %s" 的输出。
```

## 1. 采购agent 干什么

```
1.1 一句话：给一个候选（一个 1688 供应商 offer）的聊天，告诉你缺什么、下一句问什么、齐了没、收口没、要不要你定。
1.2 规则优先级（高到低）【用户定·2026-10-29】
    ① 简化采购流程 10/29（原文 2654-2661）：核心项、完成、收口
    ② 包装核实 10/20（原文 2605-2646）：取证细则——尺照秤照怎么读、裸尺寸不算包装、不混拼
    ③ 话术 10/19（原文 2668-2761）：说法和问句模板；其中「不主动询价、缺价格不挡完成」那段作废
    ④ 其余（Xunpan/README、旧读回复提示词、Mac 主控、analyze_replies 内嵌 prompt）只作历史，⛔不加载
1.3 采购agent 里面分三段，各管各的【惯例·采纳原文 84 行建议】；下文说「采购agent」都指这三段合起来，说「模型」「程序」只指其中一段
    模型   只抽事实：按 extract.schema.json 输出值＋原话＋来源，⛔不写回复、不判齐全、不折算
    程序   inquiry.py 读 rules.json 算：资料状态、动作、下一句、交人工
    发送   仍走原 send_policy.py（唯一发送方、去重、未知回执保护），采购agent ⛔不发送
```

## 2. 每轮怎么跑

```
2.1 输入包只给这些（不塞全部历史文档）【惯例·原文 87 行建议】
    当前候选（offerId、目标规格、销售单位）｜最新聊天｜已采纳事实（带原话和来源）｜未解决冲突｜各项已问次数｜最后一次发送的时间和结果｜人工暂停、人工已填
2.2 模型照 3 节抽事实 → 存成 inquiry.py 的输入 json
2.3 跑：python3 inquiry.py <输入.json>   → 输出 json；不带参数打印用法；--selftest 跑全部用例
2.4 动作=发送 时，把「下一句」交 send_policy.py；发送结果为成功才把「这次问」里的每项已问次数 +1；失败、未知不加【惯例·原文 3397 行只数成功】
```

## 3. 模型抽事实的规矩

```
3.1 只抽商家说的：来源只能引对方消息的序号或附图文件名；我方问句不能当确认
3.2 不猜：看不清、单位没说、对应哪款没说，就填「不明」或不填
3.3 价格存原样：原价＋计价单位（个/套/不明）；⛔不自己按装数折算【审查建议·原文 85 行；旧 prompt 2869 行让模型折算，数值字段只剩折算价，原价只在原话文本里】
3.4 包装标口径：包装 / 产品（裸尺寸、净重）/ 不明；对应单位：销售单位 / 单个 / 不明
3.5 匹配三档：完全匹配（商家针对目标图说有）/ 类似款 / 不匹配；类似款⛔不记完全匹配
3.6 拒绝和无法提供：商家明确不能给的项列进「无法提供」；稍等、去量、没回⛔不算
3.7 每条事实带候选 offerId；换了候选，旧事实不再算
3.8 商家反问（发哪里、加微信、要多少、哪一款）只标类型，回什么由程序定
3.9 多种报价拿不准对哪款 → 不填价格，写进「待决策」
3.10 商家说的看不懂（说不出准数、指代不清、方言缩写）→ 原话写进「看不懂」，⛔不猜不凑；采购agent 把它交人工（5.6）【用户定·2026-10-30】
```

## 4. 程序怎么判（数字都在 rules.json）

```
4.1 核心项：匹配确认、采购单价（计价单位明确）、起订量（单位＝销售单位）、包装尺寸、带包装重量、包装方式、贴标
    辅助项：中性包装、每箱数量、实拍图、视频——辅助缺⛔不挡核心齐全【用户定·2026-10-29】
4.2 价格单位：计价单位＝计数，或计数＝个且计价单位是单件量词（件、条…）→ 直接用；按「个」报、卖的是 N 个一套 → 折算＝单价×N，标「折算」；
    计价单位不明 → 问「这个价是单个的，还是{销售单位}的？」；装数不明⛔不默认 1，交你定（5.3）【审查建议·原文 85 行；旧核页 3175 行缺省按 1】
4.3 每条消息最多 2 个问题（包装尺寸和重量算 1 问，价格和起订量仍算 2 问）（首轮原句固定 3 问，例外）；每项分开记数，一项问满 2 次停问这一项，不挡别的项【用户定·2026-10-29】
4.4 先后：同款 → 定制起订 → 包装尺寸重量、贴标（同款确认后第一句就一起问）→ 价格和起订量 → 包装方式 → 辅助项【用户定·2026-10-30，原顺序贴标在最后，进待人工核实时都还没问到】
4.5 收口（资料未齐已收口）：核心还缺，且每个缺项都已问满 2 次或商家明确给不了；
    或催回后 24 小时还没新回复（发出 24 小时催一次，再等 24 小时，合计 48 小时）。收口⛔不等于不做；有新回复就重算【用户定·2026-10-29；2026-10-30 由 72 小时改 48 小时】
4.10 催回：最后一句是我方、成功发出满 24 小时没回 → 催一次（问句「催回」），之后不再催；催回发出后再满 24 小时没回 → 收口（4.5），换下一家【用户定·2026-10-30】
4.6 定制款：起订量只看定制起订量；按销售单位 ≤50 算有、继续收资料；>50 记起订量缺、问「有没有类似款，有现货的？」【用户定·2026-10-21】
4.7 最后一次发送结果未知 → 先核回执，⛔不出下一句【用户定·原文 2661 行】
4.8 人工暂停 → 不出下一句；人工已填的项以人工为准，抽出来的⛔不覆盖【用户定·原文 2693 行人工暂停优先拦截；人工值不覆盖为惯例，参照找货 601 行】
4.9 包装已完成：包装尺寸和带包装重量都有就记，只作显示，⛔不据此结束收资料【用户定·原文 2660 行】
```

## 5. 什么时候交你定

```
5.1 不能贴标：照样收资料，醒目标出，⛔不自动写不做
5.2 商家只有类似款：⛔不自动接受替代，已答的不重问，等你定
5.3 我方候选的销售单位或装数本身不明【用户定·原文 2661 行】
5.4 多种报价或包装拿不准对哪款、事实互相冲突（模型写进「待决策」）
5.5 付款、下单、承诺数量、选包装：⛔一律不替你定
5.6 商家说的看不懂（3.10）→ 待人工核实，贴原话
5.7 商家确认有货（匹配确认＝完全匹配，或类似款）→ 马上交人看，⛔不等资料齐；没给的项继续问着补，人也可以自己补【用户定·2026-10-30】
5.8 人的判断攒成经验：人每判一次记一行（商家原话、人怎么判），每周整理，同一种情况几次判法一致的写成规则进本文件，以后采购agent 自己判【用户定·2026-10-30】
```

## 10. 采购agent 岗位【用户定·2026-10-29 命名；2026-10-30 改 24 小时、三条线】

```

     「询盘中」「重跑供应商」是过程，不是结局；你点了不做的款不问，单记「不做」。完成率＝完成 ÷（总款数 − 找不到货源 − 不做），目标 100%【分母去掉不做是 c总 补的】
     开始询盘满 7 天还没结局的款，日报点名【c总 定的天数，你可改】
10.2 三条线，24 小时在岗，周一到周日每天都跑【用户定·2026-10-30，原周一到周六】
     ① 询盘   第一次联系新供应商（首轮问句）；全天发，夜里发出的一律算询盘；每个号 2–4 分钟一条

     判「商家回了」：只看我们问过的店，这家最后一条是商家发的、且比上次记的时间新；⛔不只看未读（人点开过就没了）

     三、今天做了什么：排了几条询盘、几条回复，今天新进待人工核实几款
10.5 loop：循环.py 每轮＝读款 → 采购agent.py 分类 → 调度.py 排班 → 写本轮结果和记录；同一个「现在」跑几遍结果一样；

## 11. 多账号、多国家【用户定·2026-10-29 三个号分摊；2026-10-30 多国家共用】

```

11.2 名单住 账号.json：号1、号2、号3，各带 状态（正常/暂停）和备注；⛔不存密码、cookie、手机号

     ⛔不挪给别的号，⛔不自动过验证（原文 2301）；你验证完把状态改回正常，下一轮自动接上

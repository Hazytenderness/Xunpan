## 3. 三个号：一个号一个浏览器资料夹、一把锁

- 现状【实测】：只有一个 BrowserOS neo 实例（浏览器自动化，监听 `127.0.0.1:9010`，环境变量 `XUNPAN_NEO_URL` 可以改地址）；浏览器锁是全局的 `~/.cache/xunpan/browser.lock`；`neo_paused.json`／`send_paused.json`（风控暂停标记）、`last_send.txt`／`next_send.txt`（发送节奏）、`watch_state.json`（扫描游标）也都是全局一份。
- 落法：每个号一套，名字带号：资料夹 `neo_号N`、MCP 端口、`browser_号N.lock`、`neo_paused_号N.json`、`send_paused_号N.json`、`last_send_号N.txt`、`watch_state_号N.json`。号和端口的对应、号是正常还是暂停，放本机 `~/.cache/xunpan/账号状态.json`，不进 git（循环.py 已经支持 `--账号状态`）。队列写入、发送日志、报价、网站同步、git 这几把锁仍然全局共用。
- 规矩：同一时刻最多拿一把浏览器锁；核SKU 和 `site_policy` 用号1 的锁；哪个号弹了验证，只停这个号，另两个照跑（11.6）。
- **最大的未知**：neo 能不能同时开 3 个实例、各用各的资料夹和端口【未查】。只能上阿桃机试，试不通，号2、号3 的方案就得重定。

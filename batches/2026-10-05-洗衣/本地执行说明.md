# 本地执行说明（Mac 上的 Claude Code + ego 浏览器）

在 Mac 上开一个 Claude Code 会话，克隆或拉取本仓库，切到 `claude/claude-github-connection-mtu9fd` 分支，然后让它按下面的顺序做。总规则见仓库根目录 `README.md` 第五节「发送规则」。

## 第 1 步：核页（只读，不发消息）

对 `queue.json` 里的每条，打开每个 `商品链接`：

1. 记下页面上的实际卖家名、旺旺名，在售还是下架，规格列表，登录后的阶梯价和起订量，写回这条的 `页面卖家`、`旺旺名`，详细信息存到 `pages/<offerId>.json`。
2. 看 `对应款` 里的 `规格` 和 `核页提醒`，判断页面上有没有这种货：
   - 有，而且规格能对上：`状态` 改成 `待发R1`，`r1_text` 只能改 {产品} 那几个字（按页面实际叫法），模板其余部分一个字不动。
   - 页面上没有但可能做得出来：标「待确认」，交给你定，不改话术。
   - 明显不是同一种货：`状态` 改成 `款不对`，不发。
3. 提交并推送，回云端会话说一声「核页好了」。

## 第 2 步：发送（核页结果和改过的话术由你确认后再发）

- 只发 `状态 = 待发R1` 的条目，发的是 `r1_text` 原文。
- A 组、B 组交替着发，免得某一组全挤在同一个时段。
- 北京时间 9:00–18:00 发，每家间隔 2–4 分钟随机，每天最多 30 家，60 家分两天发完（每天 A、B 各 15 家）。
- 每发一条，往 `sent_log.jsonl` 追加一行，再把这条的 `状态` 改成 `已发R1`。
- 出现验证码、掉登录、找不到发送按钮、发完对话里多出不止 1 条，任何一种情况都**立刻停下**，并说明情况。

## 第 3 步：读回复（每天北京时间 10:00、16:00）

打开每个 `已发R1` 的会话，只读，不点按钮。聊天记录写到 `chats/<offerId>.json`，对方发来的图片存到 `media/<offerId>/`。然后提交推送。字段抽取和第二轮话术由云端来做。

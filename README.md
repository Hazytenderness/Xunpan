# Xunpan · 1688 询盘工作流

每两周从 ataous 站点拿一批选品清单（每款 3 家 1688 候选），给每家发询盘，收回复，抽成结构化报价，最后回写站点。

这个仓库是**唯一的记录本**：队列、话术、发了什么、对方回了什么、抽出来的报价，都存在这里，可以追溯。

---

## 一、谁在哪里干活

| 角色 | 在哪跑 | 负责 |
|---|---|---|
| **云端会话**（claude.ai/code，挂本仓库 + `ataous-site`） | 云容器 | 拉批次、去重、写话术、抽字段、写追问、出报告、回写站点 |
| **本地发送端**（Mac 上的 Claude Code + ego 浏览器，登录 1688 买家号） | 你的电脑 | 只做两件事：**按队列发消息**、**读聊天记录落盘** |

为什么要拆成两边：云容器没有你的 1688 登录态，也不该有（扫码登录、风控、验证码都需要人在旁边）。9/28 的试做已经证明 ego 浏览器能稳定发送和读取，所以发送和读取留在本地，其余全部放在云端。两边通过本仓库 `git pull / push` 交接。

## 二、双周节奏

| 天 | 步骤 | 在哪 | 产出 |
|---|---|---|---|
| D0 | ① 取名单：读站点里选品阶段 = **询价中** 的款（存在 R2 `purchase.json` 的 `选品.阶段`，站点有 Cloudflare Access，由本地 ego 用已登录页面读出来，提交到 `batches/<日期>/stage.json`） | 本地 | `stage.json` |
| D0 | ② 建队列：对上 `products.js` 的 `货源候选`，按店铺去重，同店多款合并 | 云端 | `queue.json` |
| D0 | ③ **核页**：逐个打开商品页（只读），记下实际卖家、旺旺名、SKU 列表、登录后的阶梯价和起订量、在售状态；货明显不对的标「款不对」不发 | 本地 | `pages/<offerId>.json` |
| D0 | ④ 写首轮话术：页面上已有的信息不再问，点名具体 SKU → **你过目** | 云端 | `queue.json` 里每条的 `r1_text` |
| D1–D3 | ③ 首轮发送（限速，见第五节） | 本地 | `sent_log.jsonl` |
| D1–D7 | ④ 每天读两次回复（北京 10:00、16:00），聊天原文和图片、视频落盘 | 本地 | `chats/<offerId>.json`、`media/` |
| 每次读完 | ⑤ 抽字段：把回复对应到字段，每个数附原话；生成第二轮追问 | 云端 | `quotes.jsonl`、`r2_text` |
| D2–D5 | ⑥ 第二轮发送：只问还缺的项；48 小时没回的家催一次 | 本地 | `sent_log.jsonl` |
| D7 | ⑦ 收口：3 家都没货或拒绝的款，从站点备选里补一家（要你确认） | 云端 | 补发队列 |
| D8 | ⑧ 出报告：一款一块，3 家并排；回写站点「询价方案」 | 云端 | `report.md` + 站点 PR |

## 三、话术策略（9/28 试做的教训）

试做时一次发了 10 个问题，20 小时 3 家都没回答实质内容。所以改成**两轮**：

- **第一轮只问 3 件事**：有没有货／这个规格，500 个大概什么价、起订多少，发几张实拍图。像真人买家随口问，口语，不编号，不超过 4 行。
- **第二轮按缺项追问**：对方回了价，再问包装尺寸重量、箱规、中性包装、开票点数、打样、交期、视频。一次最多问 3 项。
- 款对不上（以图搜图常匹配到"长得像"的货），第一轮先问「有没有 XX 款」，不问价。

模板见 [`templates/话术.md`](templates/话术.md)。

## 四、要拿回来的字段

| 字段 | 轮次 | 说明 |
|---|---|---|
| 是否同款／现货 | R1 | 有／无／可定做，现货数量 |
| 阶梯价 | R1 | 300 / 500 / 1000 个单价 |
| 起订量 | R1 | MOQ |
| 实拍图 | R1 | 落盘到 `media/` |
| 产品尺寸、净重 | R2 | |
| 包装尺寸、毛重 | R2 | 单个包装 |
| 箱规 | R2 | 每箱几个、外箱尺寸、毛重 |
| 中性包装 | R2 | 不带品牌和中文标识 |
| 定制 logo／彩盒 | R2 | 能否做，起订量 |
| 打样 | R2 | 样品费、天数 |
| 大货交期 | R2 | |
| 开票点数 | R2 | |
| 视频 | R2 | 落盘到 `media/` |

规矩：**每个数字附上对方原话**（`quote` 字段），抽不到就留空、标「未回答」，不猜。

## 五、发送规则（硬性）

来自 9/28 试做时踩过的坑：

1. **打开聊天**：直接开聊天页 `air.1688.com/…/def_cbu_web_im/index.html?touid=cnalichn<旺旺名>&offerId=<商品号>`（中间路径以本地发送脚本里实测的为准），**不要点商品页的「客服」按钮**（会掉登录）。旺旺名从商品页读。
2. **整段粘贴，再点「发送」按钮**。这个聊天框里 Shift+Enter 就是发送，**禁止用键盘输入多行**（9/28 第一家就是这样刷了 11 条，被对方拒绝）。
3. 发送前三项核对：收件人对、输入框内容和话术一字不差、粘贴没触发发送。发送后核对对话里只多了 1 条。任何一项不过就停。
4. **不点**右侧「AI 询盘」面板的「帮我批量询盘」（会群发给我们没选过的店）。不点下单、加购，不回复对方的其他问题。
5. **限速**：北京 9:00–18:00 发，每家间隔 2–4 分钟随机，每天最多 30 家。弹验证码或掉登录就立刻停，通知你处理，不绕。
6. 同一批里同一个店铺（同旺旺名）只发一次，多款合并成一条问。

## 六、目录

```
batches/
  2026-10-05/                  # 一个双周批次
    batch.json                 # 批次说明：来源文件、筛选口径、款数、家数
    stage.json                 # 站点上标了「询价中」的款（本地从 R2 读出）
    pages/<offerId>.json       # 核页结果：实际卖家、旺旺名、SKU、阶梯价、起订量
    queue.json                 # 询盘队列：一条 = 一家 × 一款，含话术和状态
    sent_log.jsonl             # 每次发送的记录（时间、轮次、文本、核对结果）
    chats/<offerId>.json       # 聊天原文（本地发送端读回来的）
    media/<offerId>/           # 对方发来的图片和视频（大文件不进 git，见 .gitignore）
    quotes.jsonl               # 抽出来的结构化报价，每个数附原话
    report.md                  # 本批报告
templates/
  话术.md                       # 话术模板和写法规则
schema/
  queue.schema.md              # queue.json / quotes.jsonl 字段说明
```

每条询盘的状态：`待发R1 → 已发R1 → 已回 / 未回 → 待发R2 → 已发R2 → 完成`，另有 `拒绝`、`无货`、`款不对`、`放弃`。

## 七、上一轮试做（2026-09-28，球形软毛刷）

- 发送：铂硕、优慕两家用"粘贴 + 点按钮"一次成功；畅通被 Shift+Enter 刷成 11 条，对方回「条件太多，满足不了」。
- 读取：ego 只读聊天记录可行，不掉登录。
- 结果：10 个问题发出 20 小时，没有一家回答实质内容 → 改成上面的两轮短问。
- 站点里的供应商名可能和商品页上的实际卖家不一致，**以页面为准**。
